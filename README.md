# 키움 REST API 기반 무한매수 자동매매 시스템

첨부해주신 `kiwoom-rest-api-spec.json`, 아키텍처 다이어그램, 구글시트 리포트(SOXL 무한매수 예시),
텔레그램 대시보드 설정 화면을 기준으로 설계했습니다. 실제 명세서에 있는 TR ID를 그대로 사용했습니다.

- 인증: `au10001` (토큰발급) / `au10002` (토큰폐기)
- 미국주식 주문: `ust20000`(매수) / `ust20001`(매도) / `ust20002`(정정) / `ust20003`(취소)
- 국내주식 주문: `kt10000`(매수) / `kt10001`(매도) / `kt10002`(정정) / `kt10003`(취소)
- 잔고/예수금: `kt00018`(계좌평가잔고), `ust21120`/`ust21160`(해외 예수금), `kt00001`(국내 예수금)
- 체결/미체결: `ka10075`(미체결), `ka10076`(체결), `ust21510`(미국 당일체결)
- 실시간(WebSocket): `00`(주문체결), `04`(잔고)

시트 캡처가 SOXL(나스닥, `$` 표시) 무한매수 구조라 **미국주식 API(ust2xxxx)** 를 기본 경로로 잡고,
국내주식(`kt1xxxx`)도 동일 인터페이스로 지원하도록 어댑터 패턴으로 분리했습니다.

## 1. 전체 아키텍처

첨부하신 다이어그램(사용자 → 텔레그램 → 서버 → 키움 API / Firestore / 시트) 구조를 그대로 채용하되,
"장애 시 알림"과 "양방향 승인" 요구사항을 반영해 아래처럼 확장했습니다.

```
                                ┌────────────────────┐
                                │   Cloud Scheduler   │  (5분 주기 / 08:00 액면분할 감시 등)
                                └─────────┬────────────┘
                                          │ trigger
                                          ▼
┌──────────┐   ①명령/승인 입력   ┌──────────────────────────────────────────────┐
│  사용자  │ ───────────────────▶│              텔레그램 서버 (Webhook)            │
│ (텔레그램) │◀─────────────────── │  - 인라인 키보드 (리포트/종목설정/승인)          │
└──────────┘   ⑤결과/알림 응답    └───────────────────┬──────────────────────────┘
                                                       │ webhook (격리 처리: 실패해도 주문로직 영향 없음)
                                                       ▼
                                ┌───────────────────────────────────────────────┐
                                │                Core Logic (App Server)          │

                                │  └──────┬────────┘   └────────────────────┘     │
                                │         │ 주문요청(승인 대기 or 자동)              │
                                │         ▼                                       │
                                │  ┌───────────────┐   ┌────────────────────┐     │
                                │  │ OrderExecutor  │──▶│ DedupStore(체결키)   │     │
                                │  │ (중복방지/재시도) │   │ SQLite/Firestore    │     │
                                │  └──────┬────────┘   └────────────────────┘     │
                                │         ▼                                       │
                                │  ┌───────────────┐                              │

                                │  │ (실계좌/모의계좌) │                          │     │
                                │  └───────────────┘                        │     │
                                │                                           ▼     │
                                │  ┌──────────────┐  ┌───────────────┐ ┌────────┐│
                                │  │ SheetsLogger  │  │ MarketCalendar │ │ Notifier││
                                │  │ (5분마다 업로드)│  │ (NYSE 휴일판단) │ │ TG/DC  ││
                                │  └──────────────┘  └───────────────┘ └────────┘│

                                          │                         │
                                          ▼                         ▼
                                ┌──────────────────┐     ┌─────────────────────┐
                                │  Google Sheets     │     │  Kiwoom REST API      │
                                │  (수익률/차트 기록)  │     │  (실계좌/모의계좌 분기) │
                                └──────────────────┘     └─────────────────────┘
```

**계좌 다중화**: `AccountManager`가 `config/accounts.yaml`에 정의된 계좌 목록마다
독립된 `KiwoomClient`(토큰), `StrategyEngine`(상태), `SheetsLogger`(탭/시트 분리), `logger`(로그파일 분리)
인스턴스를 생성해 격리 실행합니다. 하나의 프로세스 안에서 `asyncio.gather`로 병렬 구동하거나,
계좌별로 별도 컨테이너를 띄우는 두 가지 배포 방식을 모두 지원하도록 설계했습니다.

## 3. 대시보드 ↔ 전략 매핑

첨부하신 "자동전략 설정" 화면(1~10차 매수 하락률, 매도 익절률, 수익부스터)을 그대로
`strategy_config.json`으로 직렬화합니다.

| 화면 항목 | JSON 필드 |
|---|---|
| 1차 매수 수동진입 금액 | `first_buy_amount` |
| N차 하락률(%) → N+1차 매수 | `buy_steps[i].drop_pct` |
| N차 매수 금액 | `buy_steps[i].amount` |
| N차 수익시 → N차 이익청산 | `sell_steps[i].profit_pct` |
| 수익부스터 하락률/재매수금액/시장가/감시시간 | `profit_booster.{drop_pct, amount, order_type, watch_minutes}` |

## 4. 개발 로드맵 (단계별)

1. **1단계 (1주) – 기반 구축**: `KiwoomClient`(토큰발급/갱신, 실계좌·모의 스위치), 로깅, 예외처리, `.env` 설계.
2. **2단계 (1주) – 계좌/시세 연동**: 잔고(`kt00018`), 예수금(`ust21160`/`kt00001`), 체결/미체결(`ka10075`,`ka10076`) 연동 및 중복 방지(`DedupStore`) 확립.
3. **3단계 (1~2주) – 전략 엔진**: `InfiniteGridStrategy` 구현(매수/매도/손절/익절 모듈 분리), `RiskManager`(포지션 한도, MDD 제한).
4. **4단계 (1주) – 알림/제어**: 텔레그램 봇(인라인 키보드, 승인 플로우, 실패 격리), 디스코드 웹훅.
5. **5단계 (1주) – 데이터 기록**: 구글시트 업로드(5분 주기), matplotlib 누적수익률 차트 생성 및 드라이브 업로드.
6. **6단계 (1주) – 특수 케이스**: NYSE 캘린더, 액면분할 감시(08:00), 다계좌 병렬 실행.
7. **7단계 (1주) – 백테스트**: 실거래 로직 재사용 가능한 `Strategy` 인터페이스 기반 백테스터, 과거 데이터 로더.
8. **8단계 (3~5일) – 대시보드**: HTML 대시보드 ↔ `strategy_config.json` 연동, 저장/불러오기.
9. **9단계 (3~5일) – 배포**: Docker화, docker-compose(다계좌 컨테이너 또는 단일 프로세스 모드), 헬스체크, 재시작 정책.
10. **10단계 (지속)** – 모의계좌 최소 2주 페이퍼트레이딩 검증 후 실계좌 소액 전환, 단계적 자본 확대.

> 실계좌 투입 전 반드시 모의투자(mockDomain: `mockapi.kiwoom.com`)로 충분히 검증하시길 권장드립니다.
